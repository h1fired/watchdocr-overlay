**WatchdOcr** accepts contributions via public **pull requests**, which include changes made to the project, as well as a written description of the changes and their justification.

> **Note:** WatchdOcr is currently in **alpha** . The code style, architecture, and guidelines are still evolving, so accepting changes in the past does not guarantee that similar changes will be accepted in the future as the project evolves.

## General contribution rules

- **Branch naming:** Git Flow style. Template: ”\<prefix>/\<short-description>”, e.g.: “feature/add-ocr-backend”.
- **Commits:** A short title and description are recommended. Describe only the specific problems you solved and, if possible, explain why you did so.

### Code style

- **Python**: Just follow PEP 8. Use type hints where practical, especially in public functions and interfaces.
- **Qt/QML code:** before introducing new templates, follow the existing naming and structuring rules contained in the corresponding module.
- **Architecture:** as reported in the note, the project architecture is still raw, so improvements are recommended, but try to follow the existing implementations.

## AI/Machine Learning Policy

AI/Machine Learning systems such as Copilot, ChatGPT, Claude, and others tend to generate plausible but incorrect code, and may make incorrect assumptions about the internals of the project.

Code generated by such systems will require careful human review and possibly human correction. If you are unable to analyze the generated code and ensure that it is valid, try to find materials that will help you understand what you are writing.

> "Trust, but verify”

## Code of Conduct

Be respectful and constructive. This is a pet project maintained in your spare time - patience with the developer and other contributors is essential.
